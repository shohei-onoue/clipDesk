## 業務フロー（確認済み）

登場主体は依頼者、サーバー、編集者。別列に取り扱う資料が整理されている。

1. 依頼者が動画を撮影する。
2. 編集依頼を作成し、動画・参考資料を添付する。
3. 指示書を入力する。資料欄に記載された指示書の構成は「目的・構成・納品条件・場面別指示」。
4. 依頼者が必須項目と納期を確認する。修正が必要な場合は編集依頼の作成へ戻る。
5. 依頼者が送信する。進捗は「受付待ち」。サーバー側には「指示書保存」が置かれている。
6. 編集者が必須項目と納期を確認する。不明点等がある場合は「要確認」となり、依頼者の指示書入力へ差し戻す。
7. 編集者が動画を編集する。進捗は「編集中」。
8. 編集者が初稿動画または修正動画を送信する。サーバー側には「動画保存」が置かれ、進捗は「初稿確認」。
9. 依頼者が初稿を確認する。修正の場合は進捗「修正」となり、編集者の動画編集へ戻る。
10. 依頼者がOKとした場合は編集者の「投稿」へ進む。進捗は「投稿済」。最終動画は資料欄の「納品ライブラリ」に対応する。

## 業務フロー実装の記録（2026-11-06）

### 実装済み（コード確認・単体テスト済み／実機・実環境は未確認）

- 依頼作成：`ChatScreen` で依頼名・目的・構成・納品条件・動画・参考資料・場面別指示・納期を実際に入力/選択。固定の質問順で、AIによる指示書生成は使わない。`BriefConfirmScreen` に入力した実データを表示し、「修正する」で戻れる。必須項目・動画・納期を検証し、送信で依頼と指示書を保存して「受付待ち」にする。
- 編集者：`HomeScreen`（編集者ホーム）、`RequestListScreen`（依頼確認）、`RequestDetailScreen` で指示書・添付・納期を確認。「編集を開始」→編集中、「要確認にする」（理由必須）→要確認。
- 要確認：依頼者が詳細から指示書を修正して再送信（`resubmitBrief`）。
- 動画提出：編集者が初稿/修正動画をアップロード（`submitVideo`）。保存成功後に「初稿確認」にし、依頼者へ通知。保存失敗時は状態・通知を変えない。
- 依頼者の確認：詳細・通知から提出動画を再生。修正指示→「修正」＋編集者へ通知。承認→承認した版を保存し編集者へ通知（状態は「初稿確認」のまま）。
- 投稿：承認済みの依頼のみ、編集者の「投稿完了にする」で「投稿済」。外部投稿APIは使わない。納品ライブラリ（`DeliveryLibraryScreen`）で承認版の最終動画を再生。
- 進捗・一覧・通知：全て Firestore の実データ。進捗は「受付待ち／要確認／編集中／初稿確認／修正／投稿済」。`StepProgressCard` は主線4段階（受付待ち→編集中→初稿確認→投稿済）に、要確認・修正を分岐表示。絞り込みは状態で実際に絞る。通知は新規依頼・確認依頼・修正内容・承認・要確認・再送信。通知タップで該当案件を開く。
- 保存・権限：`requests`、`requests/{id}/submissions`、`requests/{id}/revisions`、`notifications`、`roles/{uid}`、Storage（`uploads/`、`videos/`）。状態更新はトランザクションで状態確認・更新・通知を一括実行し、通知IDは操作ごとに決まる値で重複しない。依頼IDは画面で1回採番し、送信の再試行でも1件になる。`firestore.rules`/`storage.rules` で役割・案件との関係・遷移元/遷移先・更新可能項目を制限。役割は `roles/{uid}` にあり、クライアントから書き込めない（`users/{uid}` には役割を持たせない）。

- 起動：画面を先に出し、背景で元のオープニング動画（`assets/video_web.mp4`）をループ再生しながらFirebaseなどを読み込む（`lib/core/boot.dart`）。読み込みが終わったら、演出終盤の「ログインする」、SKIP、または画面タップでフォームを開ける。REPLAYで文字演出に戻る。オープニングとログインフォームは文字サイズ設定にかかわらず標準（1倍）で表示する。
- 失敗：Firebaseの初期化に失敗したら、エラーと「再試行」を出す。
- 招待リンク（登録フォームへ）とデバッグの自動ログイン（メイン画面へ）は、起動後の1回だけ。ログアウトして戻った場合はオープニングを表示する。
- 一覧：ダッシュボードは表示中のタブの進捗だけ、ライブラリは投稿済みだけ（承認が新しい順に12件ずつ、スクロールで追加）、進捗・通知は投稿済み以外だけをサーバーから取る。ライブラリのカードごとの提出動画の購読をやめ、承認版を1回だけ読む。
- サムネイル：一覧では動画プレーヤーを起動せず、静止画（JPEG）を出す。静止画は、依頼の最初の動画（`uploads/…/thumb_0.jpg`）と提出動画（`videos/…/vN/thumb.jpg`）の保存時にWebで作る（添付の `thumbPath`、提出の `thumbPath`）。作れなかった動画と、これまでの依頼は、再生アイコンの枠のまま（動画は従来どおり開ける）。スマホアプリからの保存では、まだ作らない。
- フォント：NotoSansJPを、JIS X 0208・0213と人名の異体字（髙・𠮷・互換漢字）などに絞った（`scripts/subset_font.py`、元は `scripts/fonts_src`）。含まれない文字は代替フォントで表示される。Oswaldは端末内のフォントを使い、Google Fontsの通信をやめた。
- 要デプロイ（未実施）：`firestore.indexes.json`（ライブラリの並べ替え用の複合インデックス）、`storage.rules`（提出動画のサムネイル保存を許可）。未デプロイの間、ライブラリは全件を取って並べ替える／提出動画のサムネイルは保存されず代替表示になる（どちらも動く）。

### ログイン後の読み込み

- 通知は、状態確認が必要な通知が参照する案件だけを購読する。参照が30件を超える場合は進行中案件の購読を使い、履歴全体の分割取得を避ける。承認・取り消し通知だけの場合は案件を取得しない。既読・非表示の更新で通知の購読を作り直さない。
- ダッシュボードと案件詳細では、画面内で重複していた役割・案件取得を減らす。進捗一覧はスクロール位置に応じてカードを描画する。ライブラリは、同じ画面で再表示した承認動画の情報を再利用する。

## ライブラリへの完成動画の追加（2026-11-26）

ユーザー指示。ライブラリに、すでに完成している動画を直接アップロードできる。指示書はなく、内容はダイアログで入力する。FigJamにはない流れ。

- 操作：ライブラリ右下の「＋」→ダイアログで、動画（mp4・mov・m4v・webm）、動画タイトル、投稿者名、アップロード日時を入力して「アップロード」。投稿者名は自分の名前、日時はアップロードを押した時刻が初期値で、どちらも直せる（今より先の日時にはできない）。
- カード：題名の欄に動画タイトル、日時の欄にアップロード日時、編集者名の欄に投稿者名を出す。配信先アイコンは出ない。再生画面に資料のボタンは出ない。
- 保存：`requests` に `source: 'library'`、`status: 'posted'`、`approvedVersion: 1` の記録を作り、`submissions/v1` に動画を残す。動画と静止画は Storage の `library/{追加した人}/{記録ID}/`。ダッシュボード・通知には出ない。
- 暫定（未確定）：追加できるのは登録済みスタッフ全員。削除は、追加した本人と管理者（カードの左スワイプ）。追加後の題名などの編集はない。
- ルール（`firestore.rules`・`storage.rules`）：本人名義の直接追加と、本人の `library/` フォルダへの保存を許可した。ルールのテストを追加。2026-11-26 に `firestore.rules`・`storage.rules` をデプロイした（上の各節の「ルールは未デプロイ」も、この時点で反映済み。ライブラリ用の複合インデックスも反映されていることを確認）。
