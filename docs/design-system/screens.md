# 画面ごとの設計

デザインシステム（`README.md`、`tokens.json`、`components.md`）を各画面へ適用する設計。業務ルール・権限・遷移は `docs/video-editing-flow.md` が正で、ここでは変えない。見た目と構成だけを定める。

## 共通ルール

- 背景は `AppColors.bg`、カード・入力は `surface200`、凹みは `surface300`。文字は `ink`、補足は `inkMuted`。
- 操作の色は `blue`（主ボタン、リンク、選択、フォーカス）。`amber` は「今ここ・要対応」の塗り専用で、上の文字は `onAmber`。
- 余白は `AppSpace`、角丸は `AppRadius` のみ。画面の左右余白は `s4`、セクション間は `s6`、カード内は `s3`〜`s4`。
- 状態は色だけでなく語句を添える（受付待ち／要確認／編集中／初稿確認／修正／投稿済）。
- タップ領域は44px以上。画面の主ボタンは1つ。
- 上部は `AppBar`（blue塗り、白文字）、下部は `TabBar`。画面タイトルは短い名詞。

## 状態の表示（全画面共通）

| 進捗 | 状態タグの色 | 備考 |
| --- | --- | --- |
| 受付待ち | 中立（surface300／ink） | |
| 要確認 | amber塗り／onAmber | 依頼者の対応待ち |
| 編集中 | bubbleBot／blue | |
| 初稿確認 | bubbleBot／blue＋「確認待ち」の語 | 依頼者の対応待ち |
| 修正 | amber塗り／onAmber | 編集者の対応待ち |
| 投稿済 | 緑系の完了色（track-audio）／語句「投稿済」 | |

「あなたの対応待ち」は amber の枠で示す。相手待ちは枠なし。

## 画面一覧

### 01 メイン（`/menu`、`menu_screen.dart`）
- 目的：ログイン後の入口。権限に応じて「依頼する」「編集する」「進捗状況をみる」「スタッフ管理」を出す。
- 構成：`AppBar`（メニュー、タイトル「メイン」）→ `ListRow`（遷移行）を縦に並べる。各行にアイコン、題名、1行の補足、シェブロン。
- 変更点：青いボタンの縦並びをやめ、白いカード行にする。責任者のみ「スタッフ管理」を末尾に追加する。

### 02 依頼者ホーム／03 編集者ホーム（`home_screen.dart`）
- 目的：進行中の案件と、自分の次の一手を見せる。
- 構成（上から）：`AppBar` → `TopTabs`（進行中／完了）→ 要対応サマリー（`EmptyCard` 兼用、件数と先頭の案件）→ 未読通知（最新1件と残り件数）→ 絞り込み（`Select` と `Chip`：すべて／受付待ち／要確認／編集中／初稿確認／修正、件数付き）→ `RequestCard` の2列グリッド → `TabBar`。
- `RequestCard`：サムネイル、状態タグ、題名（2行まで）、担当、進捗バーと数値、納期。納期が3日以内は amber、超過は `danger` と語句「期限超過」。要対応の案件は amber の枠。
- 依頼者のみ：`TabBar` 中央に主操作「新規依頼」（blueの丸）。
- 変更点：縦長のステップ表示カードを、2列カードと進捗バーに置き換える。ステップ4段階の詳細は案件詳細へ移す。

### 04 進捗状況（`progress_screen.dart`）
- 目的：全員分の動いている案件を横断して見る。投稿済は出さない。
- 構成：`AppBar` → `Chip` 行（進捗別、件数付き）→ `ListRow` 風の行（進捗リング、題名、担当、納期、状態タグ）を縦に並べる。
- 変更点：行ごとにカード、状態は語句付き。空のときは `EmptyCard`「動いている案件はありません」。

### 05 依頼一覧（`request_list_screen.dart`）
- 目的：自分に関係する依頼の一覧と絞り込み。
- 構成：`AppBar` → `Chip` 行 → 行（進捗リング、題名、納期、担当、状態タグ）→ 下部に主ボタン「新規依頼」（依頼者のみ）。
- 変更点：主ボタンは `TabBar` 中央の操作と重複しないよう、一覧にはどちらか一方だけ置く（依頼者は `TabBar`、編集者は無し）。

### 06 依頼確認（編集者、`request_list_screen.dart`）
- 目的：編集者が受付待ち・自分担当の依頼を確認する。
- 構成は 05 と同じ。行に「あなたの対応待ち」の amber 枠。主ボタンなし。

### 07 ドロワー（`app_drawer.dart`）
- 目的：メニューの側面パネル。
- 構成：左から、画面の約9割（最大360px）。上に `DrawerTile` を2つ（「つかいかた」「お問い合わせ」）、続けて `DrawerItem`（アイコン、題名、補足）：メイン／ホーム／新規依頼／通知（未読件数バッジ）／納品ライブラリ／設定（新規）。最下部に `ログアウト` と版数。背景は `surface200`、背面は `scrim`。
- 変更点：青い全面パネルを、白いパネルと区切り線付きの行にする。ログアウトは区切って最下部に置く。

### 08 通知（`notifications_screen.dart`）
- 目的：受信した通知の一覧。タップで該当案件を開く。
- 構成：`AppBar` → 通知行（アイコン、本文、時刻、シェブロン）。未読は題名を太字＋先頭に amber の点。既読は `inkMuted`。
- 変更点：既読管理は暫定（`notificationsSeenAt`）のまま。空は `EmptyCard`。

### 09 納品ライブラリ（`delivery_library_screen.dart`）
- 目的：承認済みの最終動画を再生する。
- 構成：`AppBar` → 2列カード（サムネイル、「投稿済」タグ、題名、納品日）。タップで再生ダイアログ。

### 10・11 チャットで依頼／修正指示（`chat_screen.dart`、`chat_widgets.dart`）
- 目的：固定の質問順で依頼や修正指示を入力する。
- 構成：`ChatHeader`（新規、タイトル、使い方）→ 会話欄 → 選択肢チップ（`Chip`）→ `ChatInput`（添付、送信）→ 主ボタン「指示内容を確認する」（会話が終わったとき）。
- 吹き出し：ボット（ナビゲーター）は左、`bubbleBot` 地。ユーザーは右、`surface200` 地＋細い枠。時刻は吹き出しの外。入力中は `TypingDots`。
- 提案カード（`SuggestCard`）：構成案や場面別指示の候補があるとき、横スクロールで見せ、星で保存。
- 変更点：LINE風の緑の返信を、青みの吹き出しに統一する。ナビゲーター画像（44px丸）は維持。

### 12 指示書確認（依頼者、`brief_confirm_screen.dart`）
- 目的：送信前に指示書の内容を確認する。
- 構成：`AppBar` → 依頼内容のまとめ（項目名は `label`、値は `body`、場面別指示は `CueRow` 風の行）→ 下部に「修正する」（副）と「依頼する」（主）。
- 変更点：1つの大きな吹き出しをやめ、項目ごとの行にする。

### 13・14 案件詳細（依頼者／編集者、`request_detail_screen.dart`）
- 目的：指示書・添付・提出動画を確認し、次の操作を行う。
- 構成：`AppBar` → 状態タグと題名 → 進捗（4段階のステップ、現在位置は amber）→ 主ボタン（編集者：「編集を開始」「承認…」ではなく文脈に応じた1つ）と副ボタン（「要確認にする」「修正を依頼」）→ 指示書（項目の行、場面別は `CueRow`）→ 添付資料（行、ダウンロード）→ 提出された動画（版 v1, v2…、再生）。
- 変更点：主ボタンは1つに絞る。「要確認にする」は理由入力を `Field` で受ける。

### 15 スタッフ管理（`staff_admin_screen.dart`）
- 目的：招待、権限の変更・取り消し（責任者のみ）。
- 構成：`AppBar` → 招待フォーム（`Field`：メール、権限は `Chip` の単一選択：編集者／依頼者／両方、責任者は `Switch` 行）→ 「招待メールを送る」（主）→ 登録待ちの招待 → スタッフの行（名前、メール、電話、権限 `Chip`、「責任者にする」`Switch`）。

### 16 スタッフ登録（招待リンクから、`register_screen.dart`）
- 構成：題名「スタッフ登録」→ `Field`（名前、メール（読み取り）、電話（任意）、パスワード（6文字以上））→ 主ボタン「登録する」。エラーは `Field` の `error` に「エラー：」付きで表示。

### 17 権限未設定
- 構成：中央に `EmptyCard`「権限が設定されていません。責任者に連絡してください」と、副ボタン「ログアウト」。

### 新規 設定（`/settings`）
- 目的：振動・アニメーションの切り替え、よくある質問など。
- 構成：`AppBar`（戻る）→ `ListRow`（スイッチ行：振動、アニメーション）→ 遷移行（共有用コード、復旧用コード、よくある質問、お問い合わせ）。
- 未確定：実装範囲（FigJam 未確定）。入口はドロワーの「設定」。

### オープニング・ログイン（`intro_painter.dart`、`login_screen.dart`）
- 変更しない。ログインのみ、`Field`、`Button` の枠・フォーカスの色をデザインシステムに揃える。

## 実装順（提案）

1. トークン適用：`AppColors`／`AppSpace`／`AppRadius` を既存画面へ（色と余白の置き換え）。
2. 共通ウィジェット：`AppBar`、`TabBar`、`ListRow`、`RequestCard`、`Chip`、`StatusTag`、`ProgressBar` を `lib/widgets/` に整える。
3. 画面：ドロワー → ホーム → 進捗・一覧 → チャット → 案件詳細 → スタッフ管理 → 設定。
4. 各画面を実機・Chrome で確認してから `/figmaout` で Figma に書き出す。
