# Clip Desk デザインシステム v2

更新日：2026-11-10

ユーザー指示「色の使い方や、デザインはこのUIをベースにします」に基づき、現在のFlutter UIを基準として再定義しました。基準は現行実装の黒背景、白文字、青いグラデーション、琥珀色の強調です。旧版のライトテーマ、トラック別の多色、白いドロワー、青一色のAppBarの規則は廃止します。過去のスキル要約と相違する場合も本資料を優先します。

## 参照と適用範囲

- 値と用途：`tokens.json`。v2では基準色・透明度・役割・部品寸法を分離しています。
- 部品の構造と操作：`components.md`。
- 画面の組み方：`screens.md`。
- 業務フロー、権限、状態遷移：`../video-editing-flow.md`。デザインの変更だけで業務仕様を変えません。
- 実装：`lib/core/app_colors.dart`、`app_tokens.dart`、`app_text.dart`、`responsive.dart`、`night_theme.dart`と既存の`lib/widgets/`。

今回の刷新は設計資料・トークンの更新です。画面の変更や既知の課題の修正完了を意味しません。基準UIはローカル実装のコードから整理しており、Figmaの再取得や実画面の目視確認は行っていません。

## 見た目の原則

1. 黒い画面の中に、白い文字と薄い面で情報の階層を作ります。
2. 青はブランド、会話の返信、操作を表します。メインとドロワーは黒から青へのグラデーションです。
3. 琥珀色は次の操作、要対応、進捗を強調します。青だけを主ボタンにする制約は廃止します。
4. 通常の情報カードは半透明の白と細い枠です。一覧の動画カードは白い詳細パネルを持つ別の部品です。
5. 色と形をそろえながら、質問、状態、次の操作を語句で伝えます。

## 色

| 基準色 | 値 | Flutter | 用途 |
| --- | --- | --- | --- |
| Ink | #1A1D20 | AppColors.ink | 画面背景、明るい面・琥珀の上の文字 |
| White | #F5F5F5 | AppColors.white | 暗い面・青の上の文字、一覧の詳細パネル |
| Blue | #0052CC | AppColors.blue | ブランド、返信、青い操作、選択の装飾 |
| Amber | #D97706 | AppColors.amber | 確認・送信の強調、要対応、進捗、注意 |

追加の赤・緑・紫や別のダーク用青は使いません。例外は、通知の件数バッジの赤（`AppColors.badgeRed`、利用者の指示）だけです。面や線は4色の透明度で作ります。White 8%＝情報面、16%＝区切り・無効背景、55%＝操作枠、70%＝補足文字。半透明の面はInkに重ねます。ポップアップなど背面が変わる場所では背景が透けて読みにくくならないようにします。

青い塗りにはWhite、琥珀の塗りにはInkを載せます。暗い背景の本文・選択文字はWhiteを基本とし、Blueだけの小さい文字は避けます。Amberは暗い面でのアイコン・枠・進捗にも使えます。注意・失敗は「要確認」「エラー」などの語句を添えます。白いパネル上ではAmberの小さい文字を使いません。

## グラデーション

- メインカード：Ink→Blue。`MenuScreen._MenuCard`の向きと停止位置を基準にします（tokensのgradient）。イラストを左、ふりがなと題名を右に置きます。
- ドロワー：同じInk→Blueの配色で、パネルの縦方向に合わせたグラデーションです。メインと停止位置まで同一とはしません。
- ヘッダー：面はInk、下端だけAmberへ変わります。全面のグラデーションボタンに転用しません。

## 文字・文言

NotoSansJPを基本に、見出し・項目名は700、説明は400を使います。画面タイトル24、セクション20、カード見出し16、本文14、補足・タグ12を基準にします。チャット本文15、確認のまとめ18は部品固有です。値はtokensのtypeを参照します。

オープニングのOswaldは演出専用です。未使用のJetBrains Monoやトラック別書式を全画面の必須仕様にしません。タイムコードを扱う機能を追加する場合は桁をそろえ、形式を明記します。

説明は「です・ます」調、操作名は短い名詞・動詞です。現行の`Menu`・`List`は基準画面固有の表記として記録し、他画面まで英語化しません。エラーは「エラー：原因。次の操作」の形にし、内部の例外文字列をそのまま利用者向け本文にしません。

## 形・寸法

余白はAppSpace（4/8/12/16/24/32）を使います。標準の左右余白・カード内側は16、要素間8〜12、セクション間24を基本にします。

AppRadius（4/8/12/20/999）は維持します。現行UI固有のカード15、チャットの吹き出し18・尾側4、入力24、確認CTA20はtokensのcomponentに別途記録します。これらは現在コードに数値で存在するため、変更時に`app_tokens.dart`へ対応する名前を追加してから参照します。既存のlg=12を一律15へ変更しません。

基準画面は390×844、寸法の幅比率は430pxで頭打ちです。画面自体は全幅です。操作領域は44px以上を確保し、画面の高さに比例して縮めません。長文・文字拡大時は高さを増やし、スクロールできるようにします。

## 操作と状態

主操作は同じ作業領域に1つです。副操作は薄い面か枠で階層を下げます。ナビゲーションの主入口と、案件内の実行ボタンは役割を分けて扱います。

状態は受付待ち／要確認／編集中／初稿確認／修正／投稿済。タグの現行配色はBlue＋White（受付待ち・編集中・投稿済）、Amber＋Ink（要確認・初稿確認・修正）です。「投稿済だから緑にする」という旧ルールは廃止します。

読み込み、空、失敗、無効、処理中を区別します。無効には理由、失敗には次の操作を添えます。操作アイコンにはtooltip・読み上げ名を付け、タブには現在地を伝えます。

## 移行・確認

既存の色定数と余白・角丸定数は削除しません。新規UIは既存部品を優先し、部品の値は定数を経由して使います。既存の直書きは画面変更に合わせて移行します。

実装時には狭い画面・横向き・文字拡大・キーボード表示を確認し、読み込み・空・失敗も確認します。コードを変更した場合は`flutter analyze lib`と`flutter test`を実行します。

既知の改善事項はscreens末尾に分けて記載しています。現行の見た目を基準にしても、読めない文字や押しにくい領域を標準として固定しません。

## アイコン

アイコンは Figma「icon_list」(node 273:987) の SVG（`assets/icons/`）を、`lib/widgets/app_icon.dart` の `AppIcon(AppIcons.xxx, color: …)` で使います。単色で、色は4色から選びます。塗りつぶし版（`…Fill`）は選択中・現在地に使い、未選択は線画版です。Material の `Icons` は、この一覧にない用途（再生・ダウンロードなど）に限ります。
